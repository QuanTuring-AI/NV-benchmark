# Vol.1-B · closed-loop concurrency (P17) — what is here and how to rebuild what is not

Three request shapes, one NIM container each (Llama 3.1 8B Instruct, NIM 2.0.12, no Guardrails), swept with NVIDIA AIPerf 0.11.0 at
concurrency 1 · 4 · 16 · 32 · 64 · 128 · 256 · 512 and judged against the MLPerf Inference v5.1 Llama 3.1-8B latency objectives (p99).

| Profile | Input / output shape | Directory |
|---|---|---|
| C | synthetic, ISL 200 ± 50, OSL 200 ± 50, `ignore_eos` | `C/` |
| S | CNN-DailyMail 3.0.0 validation articles in the MLPerf summarisation template, `max_completion_tokens` 128, EOS respected | `S/` |
| R | synthetic, ISL 3500 ± 300, OSL 500 ± 50, `ignore_eos` (+ two fresh-container re-runs at 128 and 256) | `R/` |

Per profile: `prediction_<P>.json` + `.sha256` (frozen before the run) · `main/levels.jsonl` (one line per level, written as each level ends) ·
`main/cNNNN/profile_export_aiperf.json|csv` (AIPerf summary per level) · `main/analysis.json` · `main/container/` (GPU context, startup log excerpt,
`/metrics` at READY, first request discarded). `slo_margins.json` gives each verdict's distance to its SLO limit. `calibration/` holds the instrument check.

## Files kept out of the repository and how to regenerate them

AIPerf writes, per level, `inputs.json` (every prompt sent), `profile_export.jsonl` and `profile_export_raw.jsonl` (every request and response). They are not
committed: they contain free model output that cannot be reviewed line by line, and for profile S they are ~60 MB per level. Everything needed to rebuild them is recorded:

- **C and R prompts** are generated by AIPerf itself from the tokenizer and the seed. Each level's exact command line is in `main/levels.jsonl` (`command`); the seed is `20260915 + concurrency`. Re-running that command against any OpenAI-compatible endpoint reproduces `inputs.json`.
- **S prompts** come from the public dataset. Build the input file with

  ```bash
  python vol1b/scripts/p17_build_datasets.py <tokenizer_dir> <data_dir> datasets/datasets_summary.json
  ```

  which downloads `abisee/cnn_dailymail` config `3.0.0` split `validation` (13,368 articles, no filtering, no truncation), wraps each article in the template recorded in
  `datasets/datasets_summary.json`, and writes `S_cnn_dailymail_validation_mlperf_template.jsonl` (SHA-256 in the same summary file). AIPerf then shuffles it per level with the seed above (`--dataset-sampling-strategy shuffle`).
- **Tokenizer**: the `tokenizer.json` / `tokenizer_config.json` of Llama 3.1 8B Instruct as shipped in the NIM model cache; their SHA-256 are in `datasets/datasets_summary.json`.
- **Responses** are regenerated by re-running the level; with `temperature 0` and the same engine they are expected to match, but this is not asserted.

The scripts (`vol1b/scripts/p17_*.py|sh`) are the ones whose SHA-256 the prediction files record.

## De-identified fields in the AIPerf outputs

AIPerf writes the machine it ran on into its outputs: the artifact directory, the tokenizer path, the full command line and, for
profile S, the input-file path. In the committed `profile_export_aiperf.json` files (four fields) and `levels.jsonl` files (the
`command` list) the local user-home prefix has been replaced by `<HOME>`; every other byte is unchanged. `deidentification_ledger.json`
lists each file with the SHA-256 of the original and of the committed version and the number of replacements. The originals are kept
locally, outside version control. Recomputing `analysis.json` for every profile from the de-identified files with `p17_analyze.py`
reproduces the committed `analysis.json` files byte for byte (checked 2026-09-16).
